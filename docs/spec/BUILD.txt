Object Storage and Fine-Grained Access Control - Specification 2.6
31 October 2026

Revised design specification. Version 2.6 is 2.5 with the project owner's decision D-12:
every payload is encrypted, by the platform under decision-bound keys by default (server
mode) or by the client in buckets that opt into client mode, and share grants let a user
name a reader where policy honors them. See ERRATA-2.5-to-2.6.md. Version 2.5 reconciled
2.4 with decisions D-01 to D-03; see ERRATA-2.4-to-2.5.md.
Security boundaries and acceptance invariants remain at the paper's existing level;
fixture mechanics and evidence formats remain in the companion files.

Main deliverables:
  fine-grained-access-spec-v2.6.tex - standalone expanded LaTeX
  fine-grained-access-spec-v2.6.pdf - compiled document

Compile the standalone source with Tectonic 0.17.0 or a compatible LaTeX engine:
  tectonic --keep-logs fine-grained-access-spec-v2.6.tex

Modular source:
  main.tex, p00..p06-*.tex, appendix-*.tex, references-body.tex
  mapping.csv, vectors/ (including test-families.json), tools/, generated/
  crypto-format-profile.tex - supplementary byte layout, not part of main paper
  engineering-notes.tex - supplementary research/code organization notes
  ERRATA-2.5-to-2.6.md - what changed from 2.5 (encryption modes, D-12)
  ERRATA-2.4-to-2.5.md - what changed from 2.4 and what was left for the owner
  HANDOFF.md - brief for the session that implements against this specification

For structural validation and table generation:
  python3 -I tools/check_spec.py
  tectonic --keep-logs main.tex
Use --check-only to validate without rewriting generated/.

See the checker help and vector notes for per-release qualification. Structural
validation and document compilation do not qualify an implementation. Legacy
scenario-only cases need concrete fixtures and actual run evidence.

The optional historical mapping check accepts --v13 PATH. Without the original
v1.3 source, it checks the historical mapping row count only.

Two deployment profiles are distinguished from 2.5: local (single node, the R1 target) and
ha (the multi-node topology, qualified only when deployed). The checker feature ha gates the
multi-node cases (family T-16, vectors V-123 and V-124).

Production conformance, concurrency/recovery runs, cryptographic-library interoperability
and performance remain separate implementation qualification work.
